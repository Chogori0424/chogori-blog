# 文章代码块可读性设计

## 目标

优化文章里的代码块和提示词块，让读者在中文阅读环境下更容易阅读长文本。

本次重点解决两个问题：

- 复制按钮默认常显，遮挡右上角内容，视觉上干扰阅读。
- 长提示词或长文本行默认横向滚动，读者需要拖动滚动条从左到右阅读，可读性差。

本文件只定义设计方向，不直接修改组件或样式代码。

## 已确认方案

采用推荐方案：统一改所有文章 `pre > code` 的阅读和复制交互，而不是只针对某一种语言或某一篇文章。

理由：

- 文章中的代码块、配置片段和提示词块都由同一个 `CodeCopy.astro` 增强，集中修改更稳定。
- 新旧文章可以同时受益，不需要改 Markdown 写法。
- 复制按钮和换行行为属于代码块组件级体验，放在组件层维护最清晰。

## 交互设计

复制按钮默认隐藏。

显示条件：

- 鼠标悬停在 `.code-block-wrapper` 上时显示。
- `.code-block-wrapper` 内部获得键盘焦点时显示。
- `.code-copy-button` 自身获得焦点时显示。
- 点击复制后，按钮保持可见并切换为 `已复制`，随后按现有延迟恢复为 `复制`。

隐藏方式：

- 使用 `opacity: 0` 和 `pointer-events: none` 避免按钮在隐藏状态下挡住文本或误触。
- 显示状态恢复 `opacity: 1` 和 `pointer-events: auto`。
- 过渡只做透明度变化，避免按钮出现时造成布局跳动。

可访问性：

- 保留 `aria-label="复制代码"` 和复制后的 `aria-label="代码已复制"`。
- 键盘用户可以通过 `:focus-within` 看见按钮。
- 不移除按钮，只做视觉隐藏和指针事件控制，避免脚本逻辑复杂化。

## 换行设计

所有文章代码块默认自动换行。

样式规则：

- `pre` 使用 `white-space: pre-wrap`，保留原有换行和缩进。
- `pre > code` 使用 `white-space: inherit`，避免 code 元素恢复不换行。
- 代码块使用 `overflow-wrap: anywhere`，处理超长 URL、长命令、长中文提示词和连续字符。
- 保留 `max-width: 100%`，不让代码块撑破文章容器。
- 不依赖横向滚动作为默认阅读方式。

权衡：

- 对普通代码来说，自动换行可能不如横向滚动保持原始排版严格。
- 但当前博客面向文章阅读，且用户明确要求避免长文本必须左右拖动阅读，所以默认换行优先。
- 如果后续需要严格排版代码块，可以再引入单独语言或类名作为例外，不在本次范围内做复杂分支。

## 视觉设计

代码块仍保持现有背景、边框、字号和圆角风格。

复制按钮：

- 继续放在右上角。
- 默认不占据读者注意力。
- 显示时保持现有胶囊按钮样式。
- 代码块右侧保留安全内边距，避免按钮出现时压住第一行或长行内容。

移动端：

- 同样默认隐藏复制按钮。
- 触摸设备上，当按钮被焦点触发或用户触达代码块时显示。
- 自动换行后应避免出现横向滚动条。
